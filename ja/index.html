01 / THE MODEL

Nimコンパイラの出力を、
観測できるランタイムへ。

Nimonyは解析・型検査・lowering・IR生成を担います。GUDGEONはその先で、Nimプログラムを動かし、止め、測り、別の実行エンジンへ渡します。

GUDGEONは第一に、NimのためのVMです。最初の入力はNIFですが、実行境界をtyped, lowered program IRに置くことで、単一のフロントエンドを超えて進化できる設計にします。

02 / ONE PROGRAM, TWO ENGINES

解釈とコンパイルを、
同じ地図から。

NIF / Final IRをVM専用bytecodeとして閉じ込めず、解釈とコンパイルの共通境界として扱います。どちらの実行方式でも、Nimのソース位置・型・フレーム情報を保ちます。

AIMMEDIATE PATH

Nim VM

Nimプログラムをすぐに実行し、命令・フレーム・値をその場で観測します。デバッグ可能性は後付けのアダプターではなく、実行モデルそのものに組み込みます。

gudgeon run app.nif
step / pauselocalsevaluate
BPERFORMANCE PATH

Native

同じNim IRをAhead-of-Timeでコンパイルします。C/NIFC、LLVM、直接codegenのいずれにも接続でき、プロジェクトをひとつの性能バックエンドに固定しません。

gudgeon build app.nif

06 / TECHNICAL GOALS

ひとつのNimプログラム、
ひとつの実行面。

GUDGEONはNimを別の方法で走らせるだけではありません。コンパイラとランタイムの境界を更新し、実行・デバッグ・プロファイリング・ネイティブコンパイルで同じモデルを共有します。

01

Final IR Loader

lowered NIF / Final IRを読み込み、安定した内部Execution IRへ正規化する。

02

Debug Runtime API

breakpoint、step、stack、locals、evaluateをVMの第一級APIとして扱う。

03

Dual Engine Contract

VM executorとネイティブバックエンドが、Nimの型・ソースマップ・FFIメタデータを共有する。

04

Portable Instrumentation

デバッグ・プロファイリング・トレースの観測点を実行エンジン横断で公開する。
